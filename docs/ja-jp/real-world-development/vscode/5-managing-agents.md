GitHub Copilot をエージェント モードで使うと、コードベースの調査、変更の提案、ファイル編集、コマンド実行などを自律的に行います。VS Code の Copilot Chat では、ツールの呼び出しやファイル編集をリアルタイムに確認できます。差分をインラインでレビューし、個々の変更を適用または元に戻し、エディターを離れずに追加のプロンプトを送信して作業を調整または拡張できます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして適用します。
- セッションの途中でエージェントに追加の指示を出し、ハイ コントラストと合わせてライト モードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使用したアクセシビリティ カスタム エージェントは、ハイ コントラスト モードを実装しています。作業中にデザイン チームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライト モードの切り替えも追加したいとのことです。最初から新しい会話を開始するのではなく、進行中のセッションに追加の指示を出します。

## Copilot の進行状況を監視する

Copilot Chat ビューでは、エージェントが調査したファイル、実行したコマンド、提案した編集など、各ステップを確認できます。ファイルの編集は差分と **Keep** / **Undo** のコントロールとともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールして各ツールの呼び出しを確認します。ファイルの読み込みや編集、実行を求めるターミナル コマンドが表示されます。
3. ファイル編集の提案があると、差分がチャット内に表示されます。
   - **Keep** を選択して変更を適用します。
   - **Undo** を選択して変更を元に戻し、エージェントに再試行させます。
4. チャット上部の **Files changed** を開くと、このセッション中にエージェントが変更したファイルをすべて確認できます。

> [!NOTE]
> ターミナル コマンドの実行などで許可が必要な場合、エージェントは一時停止して **Allow** のプロンプトを表示します。内容を確認し、許可してもよいコマンドだけを承認します。

5. エージェントがハイ コントラスト モードを実装し終えるまで待ちます。最終メッセージに変更の概要が表示されます。

## エージェントにライト モードを追加するよう依頼する

ハイ コントラスト モードができたら、同じ会話を続けてライト モードの切り替えを追加します。同じチャット セッションを使うため、エージェントはこれまでの作業、編集したコンポーネント、スタイルの方針、local storage の使い方を引き継ぎます。

1. Copilot Chat の入力欄から、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは既存の変更を調べ、ライト モードの変更を提案します。
3. ハイ コントラストの場合と同じように、新しい編集を 1 つずつレビューし、差分ごとに **Keep** または **Undo** を選択します。
4. エージェントの方針が希望と異なる場合 (たとえば、切り替え UI を意図しない形でリファクタリングする場合) は、チャット入力欄の横にある **Stop** ボタンで作業を止め、追加の説明を送信します。

> [!TIP]
> 進行中のセッションに指示を出すと、最初からやり直すより早く調整できます。追加プロンプトで「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う」と修正を依頼したり、「切り替えを 3 つに増やさず、既存の設定パネルにライト モードを追加する」と方向を調整したり、「両方の切り替えにキーボード ショートカットも追加する」と範囲を拡張したりできます。

## 変更されたファイルをレビューする

作業をコミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧をすべて確認します。Astro コンポーネント、スタイル、関連するテストが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタム エージェントのアクセシビリティ パターン (ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保存) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルで変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードで進行中のセッションを監視して案内し、ファイル編集ごとに差分をレビューし、変更を適用または元に戻し、コンテキストを保ちながら追加の依頼を送信して作業を拡張しました。

このレッスンでは、次のことを学びました。

- エージェントの作業をリアルタイムで監視する
- 個々のファイル編集を適用または元に戻す
- 追加プロンプトを使って進行中のセッションを調整する

次のレッスンでは、アクセシビリティの変更をプルリクエストとして公開し、このラボでローカルのカスタム エージェントが作成した変更をレビューします。
